# Security and network behavior - v30

This document describes the inspected source. It is not an independent security certification.

## Network destinations

- `docs.google.com`: downloads public CSV exports from Pa-Kai's translation spreadsheet. The spreadsheet ID and tab IDs are visible in source; no Google login or API key is used for these public exports.
- `api.live.prod.thehelldiversgame.com:443`: the game's live service. The launcher uses a local regular HTTP proxy for this host. Only selected successful API responses are considered for text replacement.
- `127.0.0.1`: dynamically selected loopback ports for the proxy and the certificate revocation list helper.

The launcher passes proxy environment variables to the game's protected startup process. It does not set the Windows system-wide proxy. `allow_hosts` in `launcher.py` restricts interception to the game API hostname. The proxy terminates TLS locally for that hostname, then connects upstream. This is why local certificate trust is requested.

## Replaced fields

`translation.py` enumerates display fields in assignments, war-season events, news, episodes, space-station actions and MOTD. A replacement requires an exact English source match and matching SHA-256 rule key. The code does not edit objective counters or completion states as part of translation. Unsupported fields and responses remain unchanged.

## Certificate and local keys

- A separate CA key is generated on the player's machine. A shared private CA key is not distributed.
- The key directory's ACL is restricted to the current Windows user and SYSTEM.
- Windows certificate trust is installed in the **current user's Root store**, using `certutil -user -addstore`. The user must approve Windows' prompt; the launcher does not click it.
- The CA has a ten-year validity period; the API leaf certificate generated by the launcher has a two-day validity period. Trust persists between launches until removed.
- Uninstall preparation uses the recorded certificate identity to request its removal. Cancellation or failure blocks that cleanup step instead of silently reporting success.

## Local data

State is normally stored in `%LOCALAPPDATA%\HD2ThaiLauncher`. This includes settings, translation caches, validation/build reports, patch ownership journals, local certificate material and diagnostic logs.

The MOTD collector saves allowlisted display strings, field paths and structural metadata locally for translation coverage. It filters keys that resemble account, token, password, cookie, user or session data. It does not intentionally save request bodies, authentication headers or full arbitrary API response dumps. That filtering is implemented in `motd_capture.py` and should be reviewed as code rather than treated as a guarantee about all future server schemas.

The inspected application code does not implement an upload of player diagnostics to Pa-Kai. Translation downloads are ordinary HTTPS requests and still expose normal connection metadata to the destination service.

## Game files and processes

The launcher checks for a running game before deployment, creates its own patch files without replacing existing destinations, and records their hashes. The watcher waits for game exit before cleanup. Changed or conflicting files are retained and reported rather than deleted. The installer uses the current user's application folder. Review `mod_session.py` and the Inno Setup template for exact file-management behavior.

The launcher uses the game's existing protected startup executable. It does not inject a custom DLL, modify the anti-cheat service, or disable Windows antivirus in the inspected source. It is unsigned; publication approval and antivirus outcomes are separate questions.

## Updates

Main translation data and validation rules are fetched fresh on launch. Main validation failures stop launch. API text has a bundled fallback and local validated cache. The launcher does not contain a self-update mechanism that downloads and executes a newer launcher binary. Public translation data can still change the generated game patches, so the source validators and pinned runtime input hashes are relevant to review.
